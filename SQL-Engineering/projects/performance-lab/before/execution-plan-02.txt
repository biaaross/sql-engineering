Performance Lab - Case 02
Execution Plan: BEFORE Optimization

Query:

SELECT
c.id AS customer_id,
c.name AS customer_name,
o.id AS order_id,
o.order_date,
o.status
FROM customers AS c
INNER JOIN orders AS o
ON c.id = o.customer_id
WHERE o.status = 'completed'
AND YEAR(o.order_date) = 2025;

Analysis:

* The query joins customers and orders using customers.id = orders.customer_id.
* The orders table is filtered by status and order_date.
* YEAR(order_date) makes the date predicate non-SARGable.
* Without a suitable composite index, SQL Server may need to scan a large portion of the orders table.
* The JOIN may require additional work to locate matching customer records.
* The existing query does not provide an efficient index access path for the combination of JOIN and filtering conditions.

Expected access pattern:

* Table/Index Scan on orders
* Filter operation for status and YEAR(order_date)
* JOIN operation between customers and orders

Expected performance characteristics:

* Large number of rows examined
* Higher logical reads
* Additional CPU cost for YEAR()
* Increased JOIN processing cost

Note:
This is a predicted execution-plan analysis.
Actual execution-plan metrics must be collected from SQL Server.
